# Recipe and Ingredient Maintenance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** ให้เจ้าของร้านแก้สูตรและวัตถุดิบจากรายการเดิมได้ เก็บไว้ให้เลือกใช้ไม่เกิน 5 เวอร์ชันต่อสินค้า และบอกปริมาณน้ำ/น้ำแข็งในสูตรโดยไม่คิดราคาและสต๊อก ด้วยข้อความไทยที่อ่านง่าย

**Architecture:** เก็บเวอร์ชันสูตรแบบไม่แก้ทับ ใช้การเก็บเข้าประวัติและปิดใช้งานแทนการลบแถว โดยใช้ transaction และล็อกแถวขณะเปลี่ยนสถานะร่วมกัน. น้ำและน้ำแข็งเป็นชนิดย่อยของวัตถุดิบ ใช้ชนิดดังกล่าวตอนสร้างแผนใหม่ เพื่อไม่สร้างรายการต้นทุนหรือสต๊อกที่ไม่จำเป็น โดยไม่แก้แผนที่ล็อกแล้ว.

**Tech Stack:** Existing Next.js App Router, React, TypeScript, Zod, Decimal.js, Drizzle/PostgreSQL, Vitest/PGlite, Playwright.

**Spec:** [Approved recipe and ingredient maintenance design](../specs/2026-11-17-recipe-and-ingredient-maintenance-design.md).

**Execution record:** [Local verification and release checks](../../operations/recipe-inventory-maintenance-verification.md). Implementation is on `codex/recipe-inventory-maintenance-continue`; production changes require separate approval.

## Global Constraints

- “เลือกใช้ได้สูงสุด 5 เวอร์ชันต่อสินค้า” รวมสูตรที่ใช้อยู่; ไม่สลับสูตรให้อัตโนมัติ ไม่ลบสินค้า ออเดอร์ หรือแถวประวัติ.
- น้ำ `ml` / `l` (เริ่ม `ml`); น้ำแข็ง `g` / `kg` (เริ่ม `g`); “แสดงปริมาณเฉพาะในสูตร” ไม่สร้างราคา 0 บาทเทียม หรือแยกรายการเตรียมไปหน้าซื้อหรือหน้าแผน.
- เจ้าของจากเซสชันเท่านั้น; ตรวจ owner และขอบเขตรายการทุก write; อ้าง ID ที่ไม่พบและของเจ้าของอื่นให้ผลแบบเดียวกัน. ตรวจฝั่งเซิร์ฟเวอร์แม้หน้าเว็บไม่แสดงปุ่ม.
- PostgreSQL write ordering: bake cycle → products เรียง ID → inventory items เรียง ID (เมื่อจำเป็นต้องล็อกหลายระดับ). หลังรอ lock ให้ตรวจสถานะใหม่ตาม isolation ของงาน; ทดสอบที่ข้าม transaction ด้วย PostgreSQL จริง.
- ภาษาไทยเฉพาะสูตร วัตถุดิบ และจุดที่พฤติกรรมเปลี่ยน: “เก็บเข้าประวัติ”, “ปิดใช้งาน”, “หน่วยที่ใช้ในสูตร”, “ไม่คิดต้นทุนและไม่ต้องนับสต๊อก”. ไม่เพิ่ม dependency.
- ตอนเริ่มทำงานให้ทำในพื้นที่แยกตาม `superpowers:using-git-worktrees` และอ่านคู่มือ Next.js ที่ติดตั้งตาม `AGENTS.md` ก่อนเขียนโค้ด: `node_modules/next/dist/docs/01-app/01-getting-started/{05-server-and-client-components,07-mutating-data,09-revalidating}.md`.
- ทดสอบกับฐานทดสอบเท่านั้น. ไม่ใช้ URL/credentials ของร้าน ไม่ใช้เซิร์ฟเวอร์พอร์ต 3000 เดิม และไม่ push, deploy หรือ migrate ฐานร้านจากแผนนี้. Commit ในแต่ละงานเป็น local checkpoint ของการลงมือในภายหลัง.

## Review Focus

1. สร้างพร้อมกันเมื่อแตะเพดาน หรือสลับสูตรระหว่างเก็บสูตรเก่า: เหลือ ≤5 สูตรที่เลือกได้และไม่เก็บสูตรที่เปิดใช้ (Tasks 3, 7).
2. Migration ขณะสูตรเก่าสุดยังเปิดอยู่ หรือสูตรเก่าถูกอ้างโดยรอบที่ล็อกแล้ว: อ่านสูตรและแผนเดิมได้ครบ (Tasks 1, 4).
3. เปิดฟอร์มไว้แล้วหน่วย/ชนิดย่อยเปลี่ยน หรือปิดวัตถุดิบชนกับการเปิดสูตร/ล็อกแผน: ไม่ตีความปริมาณเก่าด้วยหน่วยใหม่ และไม่มีแผนใหม่อ้างวัตถุดิบที่ปิดไปแล้ว (Tasks 2–5, 7).
4. สูตรใช้แป้ง + น้ำ + น้ำแข็ง แต่แป้งยังไม่มีราคา: เตือนเฉพาะแป้ง; ค่าแรง ค่าไฟ/แก๊ส และจำนวนแป้งไม่เปลี่ยน (Tasks 4, 7).
5. รอบที่มีแต่ของเตรียมและไม่มีบรรจุภัณฑ์: ไม่มีฟอร์มนับหลอก เริ่มผลิตได้ตามเงื่อนไขเดิม และไม่สร้างยอดซื้อนับใช้ของน้ำ/น้ำแข็ง (Tasks 4, 7).
